# Оплачено / Остаток по счетам — хэндофф для Admin Web (фронт)

> Для фронтенд-разработчика **админ-панели садика**.
> Закрывает пробел: раньше по частично оплаченному счёту было видно только
> `status:"partial"` — **без сумм**. Теперь видно, **сколько оплачено** и
> **сколько осталось**, плюс агрегат «долг по ребёнку» в списке детей.
>
> Источник истины — реальные контроллеры/DTO:
> `admin-invoice.controller.ts`, `invoice.dto.ts`, `child.controller.ts`,
> `child-response.dto.ts`. Все поля ниже сверены с кодом.
>
> ⚠️ Изменения на бэке готовы, но **ещё не задеплоены** — согласуй момент
> выкатки. Миграции БД нет (всё вычисляется на лету).

---

## 0. Базовые правила

- Базовый URL: `{HOST}/api/v1` (префикс `api` + версия `v1` зашиты глобально).
- Авторизация: `Authorization: Bearer <admin_access_token>`, роль `admin`.
- Детсад (tenant) — из токена админа. Заголовки садика слать не нужно.
- **Деньги** — в тенге (KZT), число. Обычно целое (`120000`), но при
  %-скидке может быть **дробным** (`13.5`) — рендери с учётом дробной части,
  не приводи насильно к int.

## 1. Новые поля в счёте (`InvoiceResponseDto`)

Появились **два новых поля** во **всех** ответах, где отдаётся счёт:

| Поле | Тип | Смысл |
|---|---|---|
| `amount_paid` | `number` | Сумма завершённых (`completed`) платежей по счёту, ₸. **Всегда присутствует** (0, если ничего не оплачено). |
| `amount_remaining` | `number` | Остаток к оплате, ₸ = `max(0, amount_after_discount − amount_paid)`. **Всегда присутствует** (0 у полностью оплаченных / отменённых / возвращённых). |

Существующие поля (`amount_due`, `discount_pct`, `amount_after_discount`,
`status`, …) **не изменились**.

### Где появились
| Метод | Путь | Примечание |
|---|---|---|
| GET | `/api/v1/admin/invoices` | список — поля в каждом элементе |
| GET | `/api/v1/admin/invoices/:id` | один счёт (+ `line_items`) |
| POST | `/api/v1/admin/invoices` | создание — `amount_paid:0`, `amount_remaining` = полный |
| POST | `/api/v1/admin/invoices/:id/manual-mark-paid` | после отметки — `amount_paid` учитывает кассовый платёж |
| POST | `/api/v1/admin/invoices/:id/cancel` | остаток отражает уже внесённые платежи |

### Пример ответа `GET /api/v1/admin/invoices/:id`
```jsonc
{
  "id": "i1a2b3c4-0005-0005-0005-000000000005",
  "child_id": "cccccccc-cccc-cccc-cccc-cccccccccccc",
  "invoice_type": "monthly",
  "amount_due": 120000,
  "discount_pct": 10,
  "amount_after_discount": 108000,
  "amount_paid": 50000,        // ← новое
  "amount_remaining": 58000,   // ← новое
  "status": "partial",
  "due_date": "2026-06-25",
  "line_items": [ /* ... */ ]
}
```

### Как рендерить
- **Карточка/строка счёта**: показывай прогресс оплаты
  `amount_paid / amount_after_discount` и явный **«Осталось: {amount_remaining} ₸»**.
- Ставь бейдж «Осталось …» именно на `status:"partial"` **и** `status:"overdue"`
  (у overdue тоже может быть частичная оплата).
- Для `status:"paid"` → `amount_remaining` будет `0` (можно показать «Оплачено полностью»).
- **Не** считай остаток на фронте из статуса — бери готовое `amount_remaining`.
- Крайний случай (под-тенговое округление у провайдера): `amount_paid` может
  быть чуть больше `amount_after_discount` (напр. счёт 13.5 ₸, списано 14 ₸) —
  тогда `amount_remaining` уже клампнут в `0` на бэке. Не показывай отрицательных.

## 2. Долг по ребёнку в списке детей (`GET /children`)

В `ChildDto` добавлено поле:

| Поле | Тип | Смысл |
|---|---|---|
| `outstanding_total` | `number \| null` | Суммарный долг ребёнка, ₸ = сумма `amount_remaining` по всем **не-terminal** счетам ребёнка (исключая `cancelled`/`refunded`; полностью оплаченные дают 0). |

**Важно про `null` vs `0`:**
- Поле заполняется **только в списке** `GET /api/v1/admin/children` (overlay считается батчем на всю страницу — без просадки производительности).
- На **одиночных** эндпоинтах ребёнка (`GET /children/:id`, create/update, …)
  оно приходит `null` — «не посчитано», а не «долга нет».
- `0` = «посчитано, ничего не должен».

### Пример `GET /api/v1/admin/children`
```jsonc
{
  "data": [
    {
      "id": "aaaa...",
      "full_name": "Айгерим Нурсултанкызы",
      "status": "active",
      "current_group_name": "Подготовительная «А»",
      "outstanding_total": 58000,   // ← новое (в списке)
      "...": "..."
    }
  ],
  "meta": { "total": 42, "limit": 20, "offset": 0 }
}
```

### Как рендерить
- Колонка/бейдж «Долг» в таблице детей: `outstanding_total > 0` → красный «{сумма} ₸»,
  `=== 0` → серый «нет долга» / прочерк, `=== null` → ничего не показывай
  (это одиночный эндпоинт, поле не посчитано).
- Фильтры/сортировки по долгу пока **нет** на бэке — если нужно, отдельный запрос.
- Хочешь экран «Должники» — сортируй/фильтруй пришедшую страницу на клиенте
  или скажи бэку, добавим серверный фильтр.

## 3. Что НЕ поменялось / границы
- Статусы счёта (`pending/partial/paid/overdue/refunded/cancelled`) — прежние.
- Существующие суммовые поля не тронуты; ничего удалять из парсинга не надо.
- Постраничная история платежей по счёту у админа уже была раньше —
  `GET /api/v1/admin/payments?invoice_id=<...>` (не в этом изменении).
- Всё это применимо ко всем провайдерам (Kaspi/BCC/cash) — не привязано к одному.
